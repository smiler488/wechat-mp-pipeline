# 写作规范（良超偏好，铁律级）

## 元规则：反馈闭环与自进化（接任务先读这一节）

> 良超 2026-11-02：「我给你提的有些写作建议如果是通用的，你应该自己优化相关 skill，
> 而不是每次都我手动提醒你。省着我每次挑这么多毛病。」

这套规范的价值不在写了多少条，而在**能不能自己长大**。所以每次交互结束前，必须走一遍下面两个闭环。

### 闭环 A：写稿自检 Loop（三层，迭代到 ✗ 清零）

不要"写完就交"。按层跑，改完重跑，**最多 3 轮**，仍有 ✗ 就把剩余项明确报给良超并说明原因。

| 层 | 做什么 | 怎么做 |
|---|---|---|
| **L1 机械层** | 缩写括注、高危行话、AI 腔、署名、标题、三件事、配图、段落长度 | 跑 `scripts/selfcheck.py "articles/<稿>.md"` |
| **L2 语义层** | "大同行读到这里会不会卡住" | 逐段过一遍：思路链条 / 方法直觉 / 公开数据集 三件事讲透了吗 |
| **L3 交付层** | 排版与视觉 | 预览 HTML 人工过一遍；封面横版 + 方版两张齐 |

**L1 是硬门槛**：有 ✗ 就不推草稿。脚本能判的绝不用记忆判——记忆会漏，脚本不会。

### 闭环 B：反馈自动沉淀（收到良超任何写作反馈时触发）

良超指出问题 → **先别急着只改那一篇**，先判定这条反馈属于哪一类：

**问三个问题：**

1. 换个主题、换个栏目，这条建议还成立吗？
2. 它是"我犯了错"，还是"这一篇恰好要这样写"？
3. **同类错误是不是第二次犯了？**（这次就是：先「技巧」裸用 22 处，再「下垫面」乱借——同一个毛病两次）

**→ 判定为通用（问题 1 成立，或问题 2 = 犯错，或问题 3 = 是）时，必须做完这 5 步：**

1. 改 `references/` 下对应规范文件（写清规则 + **触发这条规则的原话/事件**，像本文各处那样留痕）
2. **把可机械检查的部分加进 `scripts/selfcheck.py` 的规则表** —— 关键一步，规则不进表等于没立
3. 同步两处副本：`~/.workbuddy/skills/wechat-mp-pipeline/` 与项目 `.workbuddy/skills/wechat-mp-pipeline/`
4. 追加 `CHANGELOG.md`（日期 / 触发事件 / 规则内容 / commit）
5. commit + push GitHub（双机同步纪律）

**→ 项目约定或个人长期偏好**（换主题不成立、但以后都照办）→ 改项目 `.workbuddy/memory/MEMORY.md`

**→ 确实只针对这一篇**（比如这篇的结构调整）→ 只改文章，不动规范

**回复良超时必须说明：这条反馈归到哪一类、规范里改了什么、commit 号是多少。**
让他看到"提一次，以后全自动"，而不是"提一次，改一篇"。

### 闭环 C：草稿箱回流（良超在后台改稿后触发，2026-11-02 新增）

良超常常**直接在公众号后台改稿**，改完不另发一份给你。所以"他改了什么"这条反馈通道，以前是断的——他改了，本地档案不同步，规则也沉淀不下来，下一篇照样犯。

他说"我改了草稿箱里的稿件"时，按这个顺序做：

1. `python src/publish.py fetch <media_id> [本地稿.md]` —— 拉草稿正文，存 HTML + 纯文本到 `previews/_draft_backup/`，并与本地 Markdown 做段落级 diff
2. **逐条判定**：先排除格式噪声（微信把 `-` 列表渲染成 `•`、图注换行位置变化），只提取**文字**改动
3. **改回本地稿**，让本地档案 = 后台终稿（发现疑似误删/病句时先自己理顺，再在回复里点出来）
4. **走闭环 B 沉淀**：这些改动是良超用行动表达的偏好，含金量高于口头反馈，务必进规则表
5. **不要反向 update 草稿**——后台那份的排版（加粗、分隔、图文位置）是他的终稿，本地重新渲染会覆盖掉

**这条闭环的收益**：一篇稿子让他改一次，下次同类问题由 selfcheck 在 L1 拦住。

### 反向验证（每篇交付前）

改完规范后，顺手跑一遍 `scripts/selfcheck.py` 扫草稿箱里**其他**已推未发的稿子，
看有没有同类问题——新规则往往能揪出旧稿子里的同类毛病，一并修掉，别等良超再挑一次。

## 文风

- 署名统一 **smiler488**，不写"良超"。
- 第一人称视角（"我"），个人叙事感。
- **口吻像"成熟个人号作者"，不能像"AI 写的报告"**（2026-10-22 良超明确）：场景化开场、短句、允许口语化幽默。
- 拒绝 AI 腔套话：避免"在当今时代""赋能""抓手""值得注意的是""综上所述"等。
- 不用"先说结论"式导语；不过度编号分段；不堆表格——**一篇最多 1-2 张表，只留真正高信息密度的**。
- **标题平实化**（2026-10-31 良超否题实证）：资讯科普类标题主题前置、直给信息（如「袁隆平追梦奖学金：办了四届，很多农学研究生还不知道」），禁用「我读了 X 年才知道有 X」式第一人称卖关子标题。
- 技术内容硬核、可复现：代码、公式、参数给全；引用原文时给足上下文。
- 引用分级：官方一手 > 权威媒体 > 企业白皮书；**禁止自媒体来源**（知乎/小红书等）。自媒体只做内部交叉验证，不作引用源。

## 读者定位：写给大同行看（2026-11-02 良超铁律，论文学习部分尤其严格）

**默认读者 = 同一个大研究方向里、但不在该小方向的人。** 以 smiler488 为例：大方向是作物学 / 智慧农业 / 植物表型，那么讲 ENSO 多年预报、BRDF 测量、数字孪生的文章，也要让这个圈子里的人**顺着读下来就懂**，不需要中途去查资料。

能假定读者具备：本科级数理与编程常识、通用科研方法（交叉验证、显著性、误差线）。
不能假定读者具备：本子领域的术语、缩写、口头禅、约定俗成的指标阈值。

写作时遵守：

1. **先把"为什么值得做"讲透**：决策或产业背景、现行做法缺什么。大同行跟得上动机，才读得下去后面的技术细节。不要用"众所周知""显而易见"跳过铺垫。
2. **直觉领先于形式**：先一句大白话讲清模型/方法在干什么，再给公式；公式后必须跟一句"它在算什么、各项是什么"的翻译。
3. **输入数据说清来源与量级**：什么数据、时间跨度、空间分辨率、是否公开、公开在哪。
4. **评估方案讲完整**：怎么验证（留一法 / 交叉验证）、指标怎么算、多少算好、多少等于瞎猜。
5. **公开数据集与代码单独点出**：给仓库地址或 DOI，让大同行能直接复现、或借到自己的课题上。**承诺资源先建好**（2026-11-04 良超铁律）：凡写进正文的 GitHub 仓库 / 数据链接，必须在推草稿前真实创建并可访问（`gh repo view owner/repo` 或浏览器打开核验）——正文承诺即交付物，链接是死的等于骗读者。selfcheck 检查 11 会逐个 HTTP 核验，404 直接阻断。
6. **行话一律括注**：见下节。特别留意**有日常义的词**（技巧、锐利度、距平、命中率）和**跨学科借来的词**（下垫面等）——这两类最容易让大同行卡住。
7. **图题自明**：不看正文也能懂图在说什么；图中不出现未展开的缩写。
8. **禁止**：不解释就堆术语、缩写不展开、纯本子领域的口头禅。
9. **列举闭合**（2026-11-04 良超实证，合并潮篇）：正文、时间轴图、清单里并列列出的实例（学校、政策、工具……），后文必须逐一交代或明确说明取舍——列举即承诺。良超原话：「『三所样本校的家底』这个不合适，你自己举的例子，那些上海交通大学、海南大学、贵州大学、广西大学、石河子大学为什么不讲呢」。想只详写 3 个，列举时就把范围收敛到 3 个；列了 8 个就得给 8 个各一段（哪怕每条只有一两句）。属语义层自查，不可机械化，L2 时逐项核对"前面列的每个名字，后面都有下文吗"。

**自检（交付前）**：① 跑下节的缩写扫描命令；② 逐段问"大同行读到这里会不会卡住"，卡住就补括注或拆句；③ 确认全文交代了「数据集来源」「代码/数据位置」「评估口径」三件事。

## 术语与缩写：首现必括注（2026-11-02 良超铁律，优先级等同文风）

导火索是「季前产量预报」那篇：「技巧」裸用 22 处，读者第一反应是"技术窍门"。核对下来 skill 是大气科学的正式术语（全国科技名词委审定为「技巧[评]分」，英文 skill score）——**错的不是译名，是裸用**。从此定为硬规则。

1. **每个专业名词/缩写在全文首次出现时，紧跟括注**，格式 `中文（原文全称，一句解释）`。后文用简称，**不重复括注**。
2. **缩写 = 全称 + 中文名**：`FEWS NET（Famine Early Warning Systems Network，饥荒早期预警系统网络）`。
3. **术语 = 英文原词 + 它衡量什么/怎么算**，不是换个中文同义词就算解释：
   - ✅ `预报技巧（forecast skill，预报相对于简单基准如气候平均值的相对准确率）`
   - ❌ `预报技巧（预报能力）`——等于没解释。
4. **有日常义的专业词一律括注**：技巧、锐利度、距平、命中率、信噪比、归一化、显著性…… 只要读者可能按日常义理解，就括。
5. **括注一句话，25 字内**。一句说不清就改写成句中插入语（"……，也就是……，"）或紧接的独立短句。
6. **中文学界有固定译名的照用**，不要为"通俗"把术语换成大白话——读者是同行，换掉反而失准；括注用来解释，不是用来替换。
7. **图题、表格、小标题内同样适用**：图题里出现术语，同处括注或紧接图下注释。
8. 判断口径：**一个名词需要读者具备某个子领域的训练才能正确理解 → 括注**。宁可多括一次，不要读者卡住。
9. **跨学科借词慎用**（2026-11-02 实证：把气象的"下垫面"借进农业叙事，写成"下垫面异质性"，作物学读者看不懂，语义也不准）。要判断这个词在**读者所在学科**里是不是通用说法：
   - 本学科有更平常的说法 → 用平常说法（"产区之间的差异""空间异质性"）；
   - 确实没有替代 → 借用可以，但必须括注，且用**本学科的规范搭配**（气象里是"非均匀下垫面/下垫面非均匀性"，不是"下垫面异质性"）；
   - 借词只为显得专业 → 删。

自查（定稿前）：

```bash
# 扫出裸用的大写缩写，逐个确认首现处是否已括注
grep -oE '\b[A-Z][A-Z0-9-]{2,}\b' "articles/<稿>.md" | sort | uniq -c | sort -rn
```

再人工过一遍中文术语（技巧 / 锐利度 / 距平 / 命中率 / 交叉验证 / 显著性 / 归一化 …）。

## 运营话术禁用（2026-11-05 良超定，废止同日早间的"转化设计四件套"）

> 良超原话（看完【学术招聘】第 1 期样稿后）：「我还是不喜欢『本期拆解…建议收藏。文末可领取…回复【招聘】领取…【学术招聘】是新开栏目…下期预告…』这样的设计，**以后公众号还是别有这部分了，还有别写第xx期**。」

**一律不写**：文首埋点（"全文 X 字建议收藏"式）、文末领取钩子（"回复【X】领取…"）、栏目自介（"本栏目是新开…"）、下期预告、场景化转发语（"转给正在…"）、标题/图/kicker 里的期号（"第 N 期"）。

正文只留内容本身与（招聘类）免责声明；结尾固定块照常自动附加。当日早间立的"转化设计四件套"（文首埋点/领取钩子/系列化/转发语，见 CHANGELOG）同日废止，以本条为准——**钩子、埋点、系列包装都属"运营设计"，不是内容**。selfcheck 检查 12 已反向：命中这些话术即 ✗ 阻断。

## 事实核查（写稿前置义务）

- 所有关键数字必须回到一手来源核实（如 SEC 原文、论文原文、官方公告），不得照抄媒体转述。
- 媒体口径与原文口径冲突时，以原文为准，并可在文章中点出口径差异（这是"深度"的体现）。
- **时间敏感表述（2026-11-03 良超实证，双一流警示学科篇）**：引旧政策/旧名单的未来时间节点（如"2023 年接受再评价"）不得照抄成将来时——写稿时是未来、发稿时可能已过去。必须锚定成历史（"按当时的要求，原定 X 年……"）并补一句现状（截至发稿是否兑现、结果是否公开）。发布前重核全文"截至目前/预计将"类口径是否仍成立。
- **筹建机构的招生/运行表述（2026-11-06 良超实证，新型研究型大学篇）**："首批新生/开始招生/首届招生"必须落到**培养类型 + 招生资格**：研究生联合培养 ≠ 本校独立招生。筹建校（"（筹）""暂名"）的事实一律带状态限定，联培研究生入学不得写成"迎来首批新生"这类可被误读为学校已独立招本科生的笼统说法。**图与正文同等执行**——图中标签也要落到培养类型（如"2026.9 研究生联培入学"）。涉及筹建机构时，图例/校名/表格单元格都补"（筹）"标注。

## 去 AI 味写作（2026-10-27 良超改稿实证，Anthropic 招股书文）

良超后台改稿后确认"改完像人类写的了"。七条刀法，按此自查初稿：

1. **砍开场人设铺垫**：不写"作为天天用 X 的我，我把它从头到尾读了一遍"式自我介绍。第一句直接给事实。
2. **砍"导游式"过渡句**：禁「先说结论」「先把数字摆出来」「现在说最硬核的部分」「值得单独点名」「还有两处细节」「说几点不该被掩盖的」——段落之间不需要报幕，让内容直接衔接。
3. **砍元评论与自我标榜**：禁「这正是读原始文件的价值」「答案藏在附注里」「翻译成人话」「真正该看的指标是」——把判断留给读者。
4. **判词只说一次**：金句/比喻（如"估值的会计镜像"）出现一次即收，不在下一段二次总结（"这不是…恰恰是…"式复读必删）。
5. **砍假设性互动与邀功**：不用"如果你经历过…现在你知道了"式读者预设；结尾指引放平姿态（"感兴趣的朋友可以自己查看"，不写"可以去核对本文的每一个数字"）；**文末不写署名行**（账号自带署名）。
6. **时间词清除**："昨天晚上""今天凌晨"等会过期的时间锚点不写，用"X 月 X 日"或省略。
7. **碎段合并**：同一论点的相邻短段并为一段，全文段数往下压。

**保留项（去 AI 味 ≠ 去人味）**：口语化吐槽和松弛感必须保留——「更劲爆的是」「时间线也值得玩味」「对，就是 SpaceX 旗下那个」「用不够也得补差价」这类表达良超原样保留。数据密集段、反问句、犀利判断均保留。

**但 2026-11-02 第二次实证把"保留"的边界收紧了**（见下节）：技术性吐槽（"作者的取法简单粗暴"）保留，**自谦卖萌式插入语**（"（我小时候玩万花筒只看到花，人家玩万花筒直接玩进了 CVPR，惭愧。）"）删。

## 去元叙事：正文只留内容本身（2026-11-02 良超改稿实证二，CVPR 万花筒篇）

良超在后台逐句改完这篇，删改清单高度集中在同一类东西上。**总原则一句话：正文只留内容与判断本身，不留"我怎么得出这个判断""这一段要讲什么""这句话有多重要"这三层的语言。** 读者要的是结论和依据，不是作者的思维实况。

被删的原文 → 改法：

| 类型 | 原文 | 良超的处理 |
|---|---|---|
| 第一人称判断标签 | 我的判断是，三条限制里最后一条最要命 | → 三条限制里最后一条最重要 |
| 第一人称计划标签 | 我的可执行下一步：代码和标定数据都在… | → 直接写"代码和标定数据都在…" |
| 第一人称关联标签 | 这个方法对我的研究方向有直接的咬合点。 | → 整句删 |
| 段落报幕 | 差距也要摆在桌面上：／合作史的证据链很整齐。／再往前，／两处照录： | → 全部删 |
| 段末归纳 | 归纳成一句：这不是灵光一现的单点文章，而是… | → 整句删（小标题已说过，不复读） |
| 核查过程元评论 | 论文未标注通讯作者…，CVF 开放版全文也查不到邮箱信息，照实说明，不推断 | → 只留结论"论文未标注通讯作者与联系邮箱" |
| 自谦卖萌插入语 | （我小时候玩万花筒只看到花…惭愧。） | → 删 |
| 主观强度词 | 最要命／有张力／都是便宜货 | → 最重要／都很便宜 |
| 辩论式收尾引导 | 因此更准确的表述不是"万花筒可以替代多相机阵列"，而是：… | → 因此更准确的表述是：… |

配套三条硬规则：

1. **判断直接落地，不加"我的判断是"这类标签。** "我的判断是 X" → "X"。判断归谁的自然而然是作者，不必声明。
2. **段落之间不报幕。** "差距也要摆在桌面上""还有两处细节"这类导航语一律删——内容衔接本身就够了。
3. **核查动作不进正文。** 结论照写（"论文未标注通讯作者"），但不解释"我是怎么确认的"（"CVF 开放版也查不到，照实说明不推断"）。核查过程属于工作流，不属于文章。

**2026-11-04 实证三（学术造假审查篇，草稿箱回流）同律加删四类**：

| 类型 | 被删原文 | 处理 |
|---|---|---|
| 报幕式开头 | 这篇只谈手段：… | → 删（直接进入内容） |
| 树靶子再打 | 有人觉得通讯作者只是"挂个名、收个邮件"。规范文本不是这么写的。 | → 删（ICMJE/COPE 直接上） |
| 结构自述 | 把责任拆开，是五层：… | → 通讯责任：… |
| 自指清单 / 口号收束 | 我给自己定的清单是这几条，也…／还有一条不在清单里但更根本：…制度立住了…清单救不了系统性的问题。 | → 直接给清单；口号整句删 |

## 排版基准

- **必须配图**（良超 2026-10-27 反馈；**2026-11-03 密度升级**）：全文字不行，公众号文章至少配 1-2 张正文图（封面不算）。图随文走，插在信息密度最高的章节；图片必须承载真实信息（数据图表、原文截图、结构示意图），用 Wong 色系，经 `scripts/svg2png.py` 或一手来源截图产出，走 uploadimg 上传不占素材配额。
  - **视觉密度铁律（2026-11-03 良超原话：「公众号是类似 PPT 的视觉产品不是文本产品」）**：**每个 ## 主要章节至少 1 张正文图，非文献学习类全文 ≥3 张**（流程、对比、结构、时间轴、数据都可图化）；表格优先图片化；文献学习栏目维持原文图底线但同样鼓励图随文走。自检脚本已同步该规则。
  - **预览可见性**：预览 HTML 用相对路径引用 assets 图，在部分浏览器预览面板里会加载失败——交付预览时必须确认图真的显示出来（必要时把图内嵌进预览 HTML 或随预览一并交付图文件）。良超看不到图 = 没配。
  - **信息图连线纪律（2026-11-03 良超原话：「线为什么没有搭在方框上？能用直线的地方为什么要用斜线？」）**：框图/流程图/生态图的连线，① 端点必须精确落在方框边缘（中点对中点），被卡片遮挡的部分要从卡边缘起算可见段，禁止悬空、禁止差一点没搭上；② 能用水平/垂直直线就不用斜线或曲线，直角正交优先；③ 有流向的连线带箭头，方向与数据/调用流向一致；④ 此类几何问题脚本查不了，归入 L3 视觉审核——每张带连线的图，ViewImage 自检时逐线核对端点。
  - **信息图容器纪律（2026-11-03 良超原话：「太 AI 了……不同类型的文字用一个胶囊给它框住，做图的时候用圆角矩形或者是胶囊这些增加设计感，不然太 AI 了」）**：信息图里**同类型并列的信息项**（规格、清单、步骤内容、对比项）必须用**胶囊（pill）或圆角矩形容器**承载，禁止把并列文字裸排在卡片上；注脚与说明性小字除外。裸文字列表是"AI 味"信息图的典型特征，L3 视觉审核时逐卡检查。胶囊样式基准：高度 40-48px、全圆角（rx=高的一半）、浅底软色+深字（如 #EFF6FF/#0072B2、#F8FAFC/#334155、#FDF3EA/#D55E00）。
- 正文 15px / 行高 2 / 字距 .034em / 两端对齐；段落 ≤4 行；图随文走；**小标题见「小标题中性化」节**（文献学习栏目用中性信息词，资讯/观点类仍可让小标题带结论）。
- 渲染器扩展语法：`++下划线++`、`==米色高亮==`（全文 ≤1 处，见上）、`~~删除线~~`；图片 alt 自动生成居中图注；引用块为米色提示卡。
- 列表禁用原生 `<ol>/<ul>/<li>`（微信编辑器会破坏结构），渲染器已降级为字面标记段落。
- **大表格图片化**：超过 4 列 × 6 行的表格禁止直接贴 Markdown 表格，必须做成信息图（公司用真实 logo、色彩有视觉冲击力），用 `scripts/svg2png.py` 渲染。
- 结尾固定块由 publish.py 自动附加（front matter 加 `ending: 0` 可跳过）。**文献学习类另在结尾固定块之后自动追加 CTA「点击阅读全文，查看论文原文地址」**（标题【文献学习】+ front matter 有 `source_url` 即触发，2026-11-03 良超定，详见 publishing-ops.md 外链规则）。
- 目标：文章零修改直接发布。

## 搜一搜搜索优化（2026-11-06，学习微信官方《搜一搜优化教程01》）

> 官方源：微信公众平台「微信搜一搜助手」2023-01-06，《如何让公众号文章获取更多搜索流量？丨搜一搜优化教程01》
> （https://mp.weixin.qq.com/s/v00sCcW0BKchxgkRf3_bwg ）。完整规则与来源留痕见 `references/search-optimization.md`。
> 这是外部官方规范的吸收，不是良超纠错——与既有铁律冲突时以铁律为准（运营话术禁用、标题平实化等更严，照旧）。

要点四条：

1. **标题表意清晰、关键信息前置**：不隐瞒、不夸大、不标题党（欺骗性标题被官方定性为骗取排位的作弊行为，严格处理）；不堆砌关键词/符号；不过长（搜索结果页截断）也不过短（缺关键信息）。
2. **主旨句用加粗标出**（利于搜索引擎识别重点），但全文加粗克制——重点太多等于没有重点；长文必分段、必有小标题（照"小标题中性化"铁律写）。
3. **图/视频/音频为主的稿子必须配文字介绍**——搜索引擎读不懂纯图，缺文字介绍召回差；图片无模糊/变形/截断/白边/水印。
4. **发布后确认声明原创**：相同内容下搜一搜优先展示"声明原创"文章（后台人工步骤，进发布清单）。

机械层由 `scripts/selfcheck.py` 检查 14 兜底（标题堆砌/过短、过度加粗、长文缺小标题、图主文辅）。
