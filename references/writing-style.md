# 写作规范（良超偏好，铁律级）

## 元规则：反馈闭环与自进化（接任务先读这一节）

> 良超 2026-11-02：「我给你提的有些写作建议如果是通用的，你应该自己优化相关 skill，
> 而不是每次都我手动提醒你。省着我每次挑这么多毛病。」

这套规范的价值不在写了多少条，而在**能不能自己长大**。所以每次交互结束前，必须走一遍下面两个闭环。

### 闭环 A：写稿自检 Loop（三层，迭代到 ✗ 清零）

不要"写完就交"。按层跑，改完重跑，**最多 3 轮**，仍有 ✗ 就把剩余项明确报给良超并说明原因。

| 层 | 做什么 | 怎么做 |
|---|---|---|
| **L1 机械层** | 缩写括注、高危行话、AI 腔、署名、标题、三件事、配图、段落长度 | 跑 `scripts/selfcheck.py "articles/<稿>.md"` |
| **L2 语义层** | "大同行读到这里会不会卡住" | 逐段过一遍：思路链条 / 方法直觉 / 公开数据集 三件事讲透了吗 |
| **L3 交付层** | 排版与视觉 | 预览 HTML 人工过一遍；封面横版 + 方版两张齐 |

**L1 是硬门槛**：有 ✗ 就不推草稿。脚本能判的绝不用记忆判——记忆会漏，脚本不会。

### 闭环 B：反馈自动沉淀（收到良超任何写作反馈时触发）

良超指出问题 → **先别急着只改那一篇**，先判定这条反馈属于哪一类：

**问三个问题：**

1. 换个主题、换个栏目，这条建议还成立吗？
2. 它是"我犯了错"，还是"这一篇恰好要这样写"？
3. **同类错误是不是第二次犯了？**（这次就是：先「技巧」裸用 22 处，再「下垫面」乱借——同一个毛病两次）

**→ 判定为通用（问题 1 成立，或问题 2 = 犯错，或问题 3 = 是）时，必须做完这 5 步：**

1. 改 `references/` 下对应规范文件（写清规则 + **触发这条规则的原话/事件**，像本文各处那样留痕）
2. **把可机械检查的部分加进 `scripts/selfcheck.py` 的规则表** —— 关键一步，规则不进表等于没立
3. 同步两处副本：`~/.workbuddy/skills/wechat-mp-pipeline/` 与项目 `.workbuddy/skills/wechat-mp-pipeline/`
4. 追加 `CHANGELOG.md`（日期 / 触发事件 / 规则内容 / commit）
5. commit + push GitHub（双机同步纪律）

**→ 项目约定或个人长期偏好**（换主题不成立、但以后都照办）→ 改项目 `.workbuddy/memory/MEMORY.md`

**→ 确实只针对这一篇**（比如这篇的结构调整）→ 只改文章，不动规范

**回复良超时必须说明：这条反馈归到哪一类、规范里改了什么、commit 号是多少。**
让他看到"提一次，以后全自动"，而不是"提一次，改一篇"。

### 反向验证（每篇交付前）

改完规范后，顺手跑一遍 `scripts/selfcheck.py` 扫草稿箱里**其他**已推未发的稿子，
看有没有同类问题——新规则往往能揪出旧稿子里的同类毛病，一并修掉，别等良超再挑一次。

## 文风

- 署名统一 **smiler488**，不写"良超"。
- 第一人称视角（"我"），个人叙事感。
- **口吻像"成熟个人号作者"，不能像"AI 写的报告"**（2026-10-22 良超明确）：场景化开场、短句、允许口语化幽默。
- 拒绝 AI 腔套话：避免"在当今时代""赋能""抓手""值得注意的是""综上所述"等。
- 不用"先说结论"式导语；不过度编号分段；不堆表格——**一篇最多 1-2 张表，只留真正高信息密度的**。
- **标题平实化**（2026-10-31 良超否题实证）：资讯科普类标题主题前置、直给信息（如「袁隆平追梦奖学金：办了四届，很多农学研究生还不知道」），禁用「我读了 X 年才知道有 X」式第一人称卖关子标题。
- 技术内容硬核、可复现：代码、公式、参数给全；引用原文时给足上下文。
- 引用分级：官方一手 > 权威媒体 > 企业白皮书；**禁止自媒体来源**（知乎/小红书等）。自媒体只做内部交叉验证，不作引用源。

## 读者定位：写给大同行看（2026-11-02 良超铁律，论文学习部分尤其严格）

**默认读者 = 同一个大研究方向里、但不在该小方向的人。** 以 smiler488 为例：大方向是作物学 / 智慧农业 / 植物表型，那么讲 ENSO 多年预报、BRDF 测量、数字孪生的文章，也要让这个圈子里的人**顺着读下来就懂**，不需要中途去查资料。

能假定读者具备：本科级数理与编程常识、通用科研方法（交叉验证、显著性、误差线）。
不能假定读者具备：本子领域的术语、缩写、口头禅、约定俗成的指标阈值。

写作时遵守：

1. **先把"为什么值得做"讲透**：决策或产业背景、现行做法缺什么。大同行跟得上动机，才读得下去后面的技术细节。不要用"众所周知""显而易见"跳过铺垫。
2. **直觉领先于形式**：先一句大白话讲清模型/方法在干什么，再给公式；公式后必须跟一句"它在算什么、各项是什么"的翻译。
3. **输入数据说清来源与量级**：什么数据、时间跨度、空间分辨率、是否公开、公开在哪。
4. **评估方案讲完整**：怎么验证（留一法 / 交叉验证）、指标怎么算、多少算好、多少等于瞎猜。
5. **公开数据集与代码单独点出**：给仓库地址或 DOI，让大同行能直接复现、或借到自己的课题上。
6. **行话一律括注**：见下节。特别留意**有日常义的词**（技巧、锐利度、距平、命中率）和**跨学科借来的词**（下垫面等）——这两类最容易让大同行卡住。
7. **图题自明**：不看正文也能懂图在说什么；图中不出现未展开的缩写。
8. **禁止**：不解释就堆术语、缩写不展开、纯本子领域的口头禅。

**自检（交付前）**：① 跑下节的缩写扫描命令；② 逐段问"大同行读到这里会不会卡住"，卡住就补括注或拆句；③ 确认全文交代了「数据集来源」「代码/数据位置」「评估口径」三件事。

## 术语与缩写：首现必括注（2026-11-02 良超铁律，优先级等同文风）

导火索是「季前产量预报」那篇：「技巧」裸用 22 处，读者第一反应是"技术窍门"。核对下来 skill 是大气科学的正式术语（全国科技名词委审定为「技巧[评]分」，英文 skill score）——**错的不是译名，是裸用**。从此定为硬规则。

1. **每个专业名词/缩写在全文首次出现时，紧跟括注**，格式 `中文（原文全称，一句解释）`。后文用简称，**不重复括注**。
2. **缩写 = 全称 + 中文名**：`FEWS NET（Famine Early Warning Systems Network，饥荒早期预警系统网络）`。
3. **术语 = 英文原词 + 它衡量什么/怎么算**，不是换个中文同义词就算解释：
   - ✅ `预报技巧（forecast skill，预报相对于简单基准如气候平均值的相对准确率）`
   - ❌ `预报技巧（预报能力）`——等于没解释。
4. **有日常义的专业词一律括注**：技巧、锐利度、距平、命中率、信噪比、归一化、显著性…… 只要读者可能按日常义理解，就括。
5. **括注一句话，25 字内**。一句说不清就改写成句中插入语（"……，也就是……，"）或紧接的独立短句。
6. **中文学界有固定译名的照用**，不要为"通俗"把术语换成大白话——读者是同行，换掉反而失准；括注用来解释，不是用来替换。
7. **图题、表格、小标题内同样适用**：图题里出现术语，同处括注或紧接图下注释。
8. 判断口径：**一个名词需要读者具备某个子领域的训练才能正确理解 → 括注**。宁可多括一次，不要读者卡住。
9. **跨学科借词慎用**（2026-11-02 实证：把气象的"下垫面"借进农业叙事，写成"下垫面异质性"，作物学读者看不懂，语义也不准）。要判断这个词在**读者所在学科**里是不是通用说法：
   - 本学科有更平常的说法 → 用平常说法（"产区之间的差异""空间异质性"）；
   - 确实没有替代 → 借用可以，但必须括注，且用**本学科的规范搭配**（气象里是"非均匀下垫面/下垫面非均匀性"，不是"下垫面异质性"）；
   - 借词只为显得专业 → 删。

自查（定稿前）：

```bash
# 扫出裸用的大写缩写，逐个确认首现处是否已括注
grep -oE '\b[A-Z][A-Z0-9-]{2,}\b' "articles/<稿>.md" | sort | uniq -c | sort -rn
```

再人工过一遍中文术语（技巧 / 锐利度 / 距平 / 命中率 / 交叉验证 / 显著性 / 归一化 …）。

## 事实核查（写稿前置义务）

## 文献学习栏目专属

- 完整 SOP 见 `docs/文献解读类公众号SOP.md`。
- 五段式定稿：论文简介 → 期刊简介 → 作者简介 → 论文学习 → 启发。
- 标题格式：`【文献学习】 期刊缩写｜论文中文译名`。
- 禁用文学化夸张表达（"最野心勃勃的一跳"被点名）；论文贡献用中性学术语言，口语化仅限吐槽类插入语。
- 科研类封面不用质问式/数字悬念式钩子。
- **论文名词首现必括注**：ROC、ENSO、距平、预报技巧、锐利度、留一法交叉验证这类，按「术语与缩写」节规则给英文原词 + 一句解释。摘要数字引用必须带系统配置前提。
- **期刊分区用新锐分区，不用中科院分区**（2026-11-02 良超提出并已核查）：原中科院分区表发布主体已声明自 2026 年起停止更新发布；现由原核心团队以「新锐学术」名义发布《新锐期刊分区表》，指标口径延续。写法：`新锐分区（2026 版，2026-03-24 发布）：农林科学大类 1 区 TOP`。**必须带版本与发布日**——各高校认定口径不统一，部分高校仍沿用 2025 版中科院分区或 JCR 分区。涉及"能否用于评职称 / 毕业认定"时加一句以本单位文件为准，不替读者下结论。
- **受众是大同行，不是小方向同行**（良超 2026-11-02 强调）：思路、逻辑链条、可使用的公开数据集三件事必须讲透；行话全靠括注化解，不能假设读者自带背景，也不能把读者推出去查资料。

## 去 AI 味写作（2026-10-27 良超改稿实证，Anthropic 招股书文）

良超后台改稿后确认"改完像人类写的了"。七条刀法，按此自查初稿：

1. **砍开场人设铺垫**：不写"作为天天用 X 的我，我把它从头到尾读了一遍"式自我介绍。第一句直接给事实。
2. **砍"导游式"过渡句**：禁「先说结论」「先把数字摆出来」「现在说最硬核的部分」「值得单独点名」「还有两处细节」「说几点不该被掩盖的」——段落之间不需要报幕，让内容直接衔接。
3. **砍元评论与自我标榜**：禁「这正是读原始文件的价值」「答案藏在附注里」「翻译成人话」「真正该看的指标是」——把判断留给读者。
4. **判词只说一次**：金句/比喻（如"估值的会计镜像"）出现一次即收，不在下一段二次总结（"这不是…恰恰是…"式复读必删）。
5. **砍假设性互动与邀功**：不用"如果你经历过…现在你知道了"式读者预设；结尾指引放平姿态（"感兴趣的朋友可以自己查看"，不写"可以去核对本文的每一个数字"）；**文末不写署名行**（账号自带署名）。
6. **时间词清除**："昨天晚上""今天凌晨"等会过期的时间锚点不写，用"X 月 X 日"或省略。
7. **碎段合并**：同一论点的相邻短段并为一段，全文段数往下压。

**保留项（去 AI 味 ≠ 去人味）**：口语化吐槽和松弛感必须保留——「更劲爆的是」「时间线也值得玩味」「对，就是 SpaceX 旗下那个」「用不够也得补差价」这类表达良超原样保留。数据密集段、反问句、犀利判断均保留。

## 排版基准

- **必须配图**（良超 2026-10-27 反馈）：全文字不行，公众号文章至少配 1-2 张正文图（封面不算）。图随文走，插在信息密度最高的章节；图片必须承载真实信息（数据图表、原文截图、结构示意图），用 Wong 色系，经 `scripts/svg2png.py` 或一手来源截图产出，走 uploadimg 上传不占素材配额。
- 正文 15px / 行高 2 / 字距 .034em / 两端对齐；段落 ≤4 行；图随文走；小标题即结论。
- 渲染器扩展语法：`++下划线++`、`==米色高亮==`、`~~删除线~~`；图片 alt 自动生成居中图注；引用块为米色提示卡。
- 列表禁用原生 `<ol>/<ul>/<li>`（微信编辑器会破坏结构），渲染器已降级为字面标记段落。
- **大表格图片化**：超过 4 列 × 6 行的表格禁止直接贴 Markdown 表格，必须做成信息图（公司用真实 logo、色彩有视觉冲击力），用 `scripts/svg2png.py` 渲染。
- 结尾固定块由 publish.py 自动附加（front matter 加 `ending: 0` 可跳过）。
- 目标：文章零修改直接发布。
