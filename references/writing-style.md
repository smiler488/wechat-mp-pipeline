# 写作规范（良超偏好，铁律级）

## 元规则：反馈闭环与自进化（接任务先读这一节）

> 良超 2026-11-02：「我给你提的有些写作建议如果是通用的，你应该自己优化相关 skill，
> 而不是每次都我手动提醒你。省着我每次挑这么多毛病。」

这套规范的价值不在写了多少条，而在**能不能自己长大**。所以每次交互结束前，必须走一遍下面两个闭环。

### 闭环 A：写稿自检 Loop（三层，迭代到 ✗ 清零）

不要"写完就交"。按层跑，改完重跑，**最多 3 轮**，仍有 ✗ 就把剩余项明确报给良超并说明原因。

| 层 | 做什么 | 怎么做 |
|---|---|---|
| **L1 机械层** | 缩写括注、高危行话、AI 腔、署名、标题、三件事、配图、段落长度 | 跑 `scripts/selfcheck.py "articles/<稿>.md"` |
| **L2 语义层** | "大同行读到这里会不会卡住" | 逐段过一遍：思路链条 / 方法直觉 / 公开数据集 三件事讲透了吗 |
| **L3 交付层** | 排版与视觉 | 预览 HTML 人工过一遍；封面横版 + 方版两张齐 |

**L1 是硬门槛**：有 ✗ 就不推草稿。脚本能判的绝不用记忆判——记忆会漏，脚本不会。

### 闭环 B：反馈自动沉淀（收到良超任何写作反馈时触发）

良超指出问题 → **先别急着只改那一篇**，先判定这条反馈属于哪一类：

**问三个问题：**

1. 换个主题、换个栏目，这条建议还成立吗？
2. 它是"我犯了错"，还是"这一篇恰好要这样写"？
3. **同类错误是不是第二次犯了？**（这次就是：先「技巧」裸用 22 处，再「下垫面」乱借——同一个毛病两次）

**→ 判定为通用（问题 1 成立，或问题 2 = 犯错，或问题 3 = 是）时，必须做完这 5 步：**

1. 改 `references/` 下对应规范文件（写清规则 + **触发这条规则的原话/事件**，像本文各处那样留痕）
2. **把可机械检查的部分加进 `scripts/selfcheck.py` 的规则表** —— 关键一步，规则不进表等于没立
3. 同步两处副本：`~/.workbuddy/skills/wechat-mp-pipeline/` 与项目 `.workbuddy/skills/wechat-mp-pipeline/`
4. 追加 `CHANGELOG.md`（日期 / 触发事件 / 规则内容 / commit）
5. commit + push GitHub（双机同步纪律）

**→ 项目约定或个人长期偏好**（换主题不成立、但以后都照办）→ 改项目 `.workbuddy/memory/MEMORY.md`

**→ 确实只针对这一篇**（比如这篇的结构调整）→ 只改文章，不动规范

**回复良超时必须说明：这条反馈归到哪一类、规范里改了什么、commit 号是多少。**
让他看到"提一次，以后全自动"，而不是"提一次，改一篇"。

### 闭环 C：草稿箱回流（良超在后台改稿后触发，2026-11-02 新增）

良超常常**直接在公众号后台改稿**，改完不另发一份给你。所以"他改了什么"这条反馈通道，以前是断的——他改了，本地档案不同步，规则也沉淀不下来，下一篇照样犯。

他说"我改了草稿箱里的稿件"时，按这个顺序做：

1. `python src/publish.py fetch <media_id> [本地稿.md]` —— 拉草稿正文，存 HTML + 纯文本到 `previews/_draft_backup/`，并与本地 Markdown 做段落级 diff
2. **逐条判定**：先排除格式噪声（微信把 `-` 列表渲染成 `•`、图注换行位置变化），只提取**文字**改动
3. **改回本地稿**，让本地档案 = 后台终稿（发现疑似误删/病句时先自己理顺，再在回复里点出来）
4. **走闭环 B 沉淀**：这些改动是良超用行动表达的偏好，含金量高于口头反馈，务必进规则表
5. **不要反向 update 草稿**——后台那份的排版（加粗、分隔、图文位置）是他的终稿，本地重新渲染会覆盖掉

**这条闭环的收益**：一篇稿子让他改一次，下次同类问题由 selfcheck 在 L1 拦住。

### 反向验证（每篇交付前）

改完规范后，顺手跑一遍 `scripts/selfcheck.py` 扫草稿箱里**其他**已推未发的稿子，
看有没有同类问题——新规则往往能揪出旧稿子里的同类毛病，一并修掉，别等良超再挑一次。

## 全号统一写法与排版（2026-11-22 良超定，覆盖所有栏目，铁律级）

> 良超 2026-11-22 连提七条，都是**换任何栏目、任何主题都成立**的通用规则（闭环 B 判定：通用），
> 一次性覆盖文献学习 / 学术招聘 / 征稿 / 资讯观点 / 工具稿与以后所有新栏目。原话留痕：
> ①「学术招聘的skill和学术论文公众号的skill都要注意一个地方，禁用使用『「 」』而是使用双引号」；
> ②「正文如果你现在都给我加粗，那么关键句子或者要强调的名词就用『#03c160』这样的绿色来高亮」；
> ③「『单位与平台关系：上层为……』这是图注的写法，不是正文的写法」；
> ④「开头只要一段，不要太多废话，所有公众号都要遵循总分的写作逻辑」；
> ⑤「『招聘单位与团队』写的太多了，要注意重点，请精简」；
> ⑥「我们有很多解释的内容放在括号里，可以用灰色和正文区分开来」「还要善用序号列表（有序和无序的）」；
> ⑦「写作格式都要统一：字体大小、颜色、行间距、段前段后距等，该用滑动表格的用滑动表格」。

**这七条约束的是 `articles/` 稿件产物（标题 / digest / 正文 / 图注 alt / 信息图 SVG 文字）；
本规范文档里引述良超原话用的「」是文档标记，不在禁用之列。** 存量已推送稿不回改。

### 1. 引号：一律双引号，禁直角引号

正文、标题、摘要、图注、信息图文字里表示引述 / 专名 / 强调的引号，**统一用双引号 "…"**（本号既有惯例，
ASCII 直双引号），不用直角引号「」『』（竖排 / 台港习惯，与全号正文语体不一致）。信息图 SVG 里的文字同等执行。
selfcheck 检查 25 扫到「」『』即 ✗ 阻断。

### 2. 强调：绿色高亮替代加粗（详见「强调：绿色高亮替代加粗」节）

关键句、要强调的名词用 `==…==`（渲染为微信绿 #03c160 **纯文字**，不加底色 / 圆角 / 阴影——良超不喜欢阴影）；
**正文不再手写 `**加粗**` 标重点**。结构性加粗（表头、图注编号）由渲染器负责。每节 1-2 处、克制使用，不整段刷绿。
强调色全号唯一值 = `src/md2wechat.py` 的 `ACCENT_GREEN`。

### 3. 括注：解释性内容用灰色区分

术语全称、英文原词、机构注册名、来源限定、补充条件等解释性 / 补充性内容，**照常写进全角括号 `（…）`**，
渲染器（`_grey_glosses`）自动把全角括注染成次要灰 #64748B，与正文 #3f3f3f 区分，
读者一眼能跳过。**写稿时不要为此手写任何样式或标记**——照常用括号即可，灰化是渲染器统一行为。
括注仍守「首现必括注、一句 25 字内」旧规。

### 4. 列表：善用有序 / 无序列表

并列的任职条件、岗位职责、步骤、字段清单、多个岗位 / 工作地 / 维度，**优先用 Markdown 列表**
（`- ` 无序 / `1. ` 有序），别把并列项硬塞进一长段。渲染器把列表降级为悬挂缩进的字面标记段落
（`• ` / `1. `），微信编辑器不会破坏结构，手机上比长段落好读。
边界：列表用来承载**并列字段**，不是把叙述性段落拆成 1./2./3. 编号（那还是过度编号分段）；
一段仍只讲一件事，不把整篇写成碎片清单。selfcheck 检查 26 对「写了'有 N 项/条'却没用列表」给 ⚠。

### 5. 总分逻辑：开头一段总起

**所有公众号都要遵循"总分"**：开头**一个自然段**总起，直接讲清这篇文章讲什么 / 核心结论 / 岗位是什么，
不寒暄、不铺陈背景、不拆成多段引言、不写"先说结论"式报幕。随后用 ## 分节展开（分述）。
开头段可以信息密度高（一句交代主体 + 一句交代范围 + 一句交代关键条件），但**只占一段**。
selfcheck 检查 26 对「第一个 ## 之前超过 1 个正文段落」给 ⚠。

### 6. 图注与正文的语体边界

描述一张图的**视觉构成**（"上层为…下分…中部四枚胶囊并列…右侧胶囊列出…底部灰条…"）
是**图注 / 信息图说明**的语言，只属于图片 `alt`；**正文不写这种构图复述**，正文讲事实与判断本身。
图注按科研三段式「图编号 + 图标题：图中元素解释」写（检查 17），元素解释点明图里有哪几组信息、
色块 / 分区各代表什么即可，不要把制图过程 / 版面方位逐项报幕。
信息图与正文是**互补**关系：图承载结构与并列关系，正文承载事实、判断与依据，两边不互相复述。
selfcheck 检查 26 对正文段落里出现构图复述词给 ⚠。

### 7. 全号格式统一：渲染器 STYLES 是唯一真源

字号、颜色、行间距、段前段后距、字距、列表缩进、强调色、括注灰、图注、表格等**所有排版参数，
一律以 `src/md2wechat.py` 的 `STYLES` / `LIST_ITEM_STYLE` 为唯一真源**，全号所有栏目共用同一套，
**SOP 文档与稿件都不得另写内联样式、也不得在文档里固化与渲染器不同的字号 / 字距 / 段距值**
（历史 SOP 里"15px""深色底 + 霓虹紫"等旧值一律以渲染器与 `references/cover-design.md` V3 为准，废止）。
当前统一基准：正文 16px / 字重 500 / 行高 2 / 字距 .034em / 两端对齐 / #3f3f3f；
段前 0、段后 1.1em；h2 19px 带绿色左边框；图注 14px 左对齐；引用块普通灰字 14px、无底色卡片（2026-11-23 起，旧米色提示卡废止；文献学习结尾 CTA 卡片改灰底 #F5F5F5）。
**该用滑动表格的就用滑动表格**：多字段并列（岗位对照、作者表、指标对比）直接写 Markdown 表格，
渲染器自动包 `overflow-x:auto` 横向滚动容器并按列数定 min-width（检查 23）；
禁手写 HTML `<table>`、禁为省事把并列字段塞进长段落；>4 列 × 6 行的大表仍按铁律图片化。
selfcheck 检查 25 对稿件里出现手写内联样式（`style=` / `font-size` / `color:#` / `<span`）给 ✗。

**落点自检**：检查 25（引号 / 手写加粗 / 手写内联样式，✗）、检查 26（总分开头 / 列表 / 图注语体，⚠）、
检查 5.4（绿色高亮用量，⚠）、检查 24（招聘单位介绍加精简上界，⚠）。

**B. 抽象判断必须跟证据（L2 语义自审，逐段核）**

每个抽象判断后面必须落一个具体事实、数字或反例，否则删掉判断只留事实。

- 「属交叉学科」→ 判断无支撑，删；改「农业、能源、生态三个部门共用同一份水资源配额，任一个部门的需求变化都会改变另外两个的可用量」。

- 「这个方向会比较吃力」→ 改「难以完成联立求解这部分工作」，指向具体工作内容。

**C. 句式**：长短句交替，**不连续三句同结构**。三个以上并列事实改用列表，不写成一串同构分句。

**D. 结构**：第一句进核心问题，不写开场寒暄、不写总结升华段。免责声明与结尾固定块（`templates/ending_block.html`、`templates/source_cta.html`）不受此限。

**E. 语气基准**：像跟同方向的人当面讲结论——判断在前，证据紧跟，说完就停。不用形容词渲染量级（很宽、极其、非常），直接给范围、阈值或量级数字。

## 读者定位：写给大同行看（2026-11-02 良超铁律，论文学习部分尤其严格）

**默认读者 = 同一个大研究方向里、但不在该小方向的人。** 以 smiler488 为例：大方向是作物学 / 智慧农业 / 植物表型，那么讲 ENSO 多年预报、BRDF 测量、数字孪生的文章，也要让这个圈子里的人**顺着读下来就懂**，不需要中途去查资料。

能假定读者具备：本科级数理与编程常识、通用科研方法（交叉验证、显著性、误差线）。
不能假定读者具备：本子领域的术语、缩写、口头禅、约定俗成的指标阈值。

写作时遵守：

1. **先把"为什么值得做"讲透**：决策或产业背景、现行做法缺什么。大同行跟得上动机，才读得下去后面的技术细节。不要用"众所周知""显而易见"跳过铺垫。
2. **直觉领先于形式**：先一句大白话讲清模型/方法在干什么，再给公式；公式后必须跟一句"它在算什么、各项是什么"的翻译。
3. **输入数据说清来源与量级**：什么数据、时间跨度、空间分辨率、是否公开、公开在哪。
4. **评估方案讲完整**：怎么验证（留一法 / 交叉验证）、指标怎么算、多少算好、多少等于瞎猜。
5. **公开数据集与代码单独点出**：给仓库地址或 DOI，让大同行能直接复现、或借到自己的课题上。**承诺资源先建好**（2026-11-04 良超铁律）：凡写进正文的 GitHub 仓库 / 数据链接，必须在推草稿前真实创建并可访问（`gh repo view owner/repo` 或浏览器打开核验）——正文承诺即交付物，链接是死的等于骗读者。selfcheck 检查 11 会逐个 HTTP 核验，404 直接阻断。
6. **行话一律括注**：见下节。特别留意**有日常义的词**（技巧、锐利度、距平、命中率）和**跨学科借来的词**（下垫面等）——这两类最容易让大同行卡住。
7. **图题自明**：不看正文也能懂图在说什么；图中不出现未展开的缩写。
8. **禁止**：不解释就堆术语、缩写不展开、纯本子领域的口头禅。
9. **列举闭合**（2026-11-04 良超实证，合并潮篇）：正文、时间轴图、清单里并列列出的实例（学校、政策、工具……），后文必须逐一交代或明确说明取舍——列举即承诺。良超原话：「『三所样本校的家底』这个不合适，你自己举的例子，那些上海交通大学、海南大学、贵州大学、广西大学、石河子大学为什么不讲呢」。想只详写 3 个，列举时就把范围收敛到 3 个；列了 8 个就得给 8 个各一段（哪怕每条只有一两句）。属语义层自查，不可机械化，L2 时逐项核对"前面列的每个名字，后面都有下文吗"。

**自检（交付前）**：① 跑下节的缩写扫描命令；② 逐段问"大同行读到这里会不会卡住"，卡住就补括注或拆句；③ 确认全文交代了「数据集来源」「代码/数据位置」「评估口径」三件事。

## 术语与缩写：首现必括注（2026-11-02 良超铁律，优先级等同文风）

导火索是「季前产量预报」那篇：「技巧」裸用 22 处，读者第一反应是"技术窍门"。核对下来 skill 是大气科学的正式术语（全国科技名词委审定为「技巧[评]分」，英文 skill score）——**错的不是译名，是裸用**。从此定为硬规则。

1. **每个专业名词/缩写在全文首次出现时，紧跟括注**，格式 `中文（原文全称，一句解释）`。后文用简称，**不重复括注**。
2. **缩写 = 全称 + 中文名**：`FEWS NET（Famine Early Warning Systems Network，饥荒早期预警系统网络）`。
3. **术语 = 英文原词 + 它衡量什么/怎么算**，不是换个中文同义词就算解释：
   - ✅ `预报技巧（forecast skill，预报相对于简单基准如气候平均值的相对准确率）`
   - ❌ `预报技巧（预报能力）`——等于没解释。
4. **有日常义的专业词一律括注**：技巧、锐利度、距平、命中率、信噪比、归一化、显著性…… 只要读者可能按日常义理解，就括。
5. **括注一句话，25 字内**。一句说不清就改写成句中插入语（"……，也就是……，"）或紧接的独立短句。
6. **中文学界有固定译名的照用**，不要为"通俗"把术语换成大白话——读者是同行，换掉反而失准；括注用来解释，不是用来替换。
7. **图题、表格、小标题内同样适用**：图题里出现术语，同处括注或紧接图下注释。
8. 判断口径：**一个名词需要读者具备某个子领域的训练才能正确理解 → 括注**。宁可多括一次，不要读者卡住。
9. **跨学科借词慎用**（2026-11-02 实证：把气象的"下垫面"借进农业叙事，写成"下垫面异质性"，作物学读者看不懂，语义也不准）。要判断这个词在**读者所在学科**里是不是通用说法：
   - 本学科有更平常的说法 → 用平常说法（"产区之间的差异""空间异质性"）；
   - 确实没有替代 → 借用可以，但必须括注，且用**本学科的规范搭配**（气象里是"非均匀下垫面/下垫面非均匀性"，不是"下垫面异质性"）；
   - 借词只为显得专业 → 删。
10. **模型 / 算法 / 工具名同样要括注（2026-11-23 良超发布稿追问「BlendMask 为什么没加括号解释」）**：括注义务不限于全大写缩写。`BlendMask（一种实例分割模型，把每株植株从背景中单独框出）`、`ResNet18（残差网络的一种 18 层结构）`、`GoogLeNet、AlexNet、VGG16` 这类专名，首现都给一句"它是什么、干什么用"。selfcheck 检查 30 对常见模型名逐个核。

自查（定稿前）：

```bash
# 扫出裸用的大写缩写，逐个确认首现处是否已括注
grep -oE '\b[A-Z][A-Z0-9-]{2,}\b' "articles/<稿>.md" | sort | uniq -c | sort -rn
```

再人工过一遍中文术语（技巧 / 锐利度 / 距平 / 命中率 / 交叉验证 / 显著性 / 归一化 …）。

## 事实核查（写稿前置义务）

- 所有关键数字必须回到一手来源核实（如 SEC 原文、论文原文、官方公告），不得照抄媒体转述。
- 媒体口径与原文口径冲突时，以原文为准，并可在文章中点出口径差异（这是"深度"的体现）。
- **名单盘点类内容逐人回官方名单页核验**（2026-11-08 良超实证，农业院士版图篇：凭记忆列中科院涉农院士，误列王二涛（非院士）、漏张启发/刘耀光/黄路生/陈化兰/张克勤 5 人，良超复核抓出）：院士/人才帽子/高校/机构这类"名单即内容"的文章，**每个名字必须对照官方名单页**——两院走 casad.cas.cn 学部名单与 cae.cn 院士名单页，高校/机构走官网；不得凭记忆，不得只信媒体转述（自媒体名单常漏常错）。selfcheck 检查 20 兜底提醒。
- **时间敏感表述（2026-11-03 良超实证，双一流警示学科篇）**：引旧政策/旧名单的未来时间节点（如"2023 年接受再评价"）不得照抄成将来时——写稿时是未来、发稿时可能已过去。必须锚定成历史（"按当时的要求，原定 X 年……"）并补一句现状（截至发稿是否兑现、结果是否公开）。发布前重核全文"截至目前/预计将"类口径是否仍成立。

- **筹建机构的招生/运行表述（2026-11-06 良超实证，新型研究型大学篇）**："首批新生/开始招生/首届招生"必须落到**培养类型 + 招生资格**：研究生联合培养 ≠ 本校独立招生。筹建校（"（筹）""暂名"）的事实一律带状态限定，联培研究生入学不得写成"迎来首批新生"这类可被误读为学校已独立招本科生的笼统说法。**图与正文同等执行**——图中标签也要落到培养类型（如"2026.9 研究生联培入学"）。涉及筹建机构时，图例/校名/表格单元格都补"（筹）"标注。

## 去 AI 味写作（2026-10-27 良超改稿实证，Anthropic 招股书文）

良超后台改稿后确认"改完像人类写的了"。七条刀法，按此自查初稿：

1. **砍开场人设铺垫**：不写"作为天天用 X 的我，我把它从头到尾读了一遍"式自我介绍。第一句直接给事实。
2. **砍"导游式"过渡句**：禁「先说结论」「先把数字摆出来」「现在说最硬核的部分」「值得单独点名」「还有两处细节」「说几点不该被掩盖的」——段落之间不需要报幕，让内容直接衔接。
3. **砍元评论与自我标榜**：禁「这正是读原始文件的价值」「答案藏在附注里」「翻译成人话」「真正该看的指标是」——把判断留给读者。
4. **判词只说一次**：金句/比喻（如"估值的会计镜像"）出现一次即收，不在下一段二次总结（"这不是…恰恰是…"式复读必删）。
5. **砍假设性互动与邀功**：不用"如果你经历过…现在你知道了"式读者预设；结尾指引放平姿态（"感兴趣的朋友可以自己查看"，不写"可以去核对本文的每一个数字"）；**文末不写署名行**（账号自带署名）。
6. **时间词清除**："昨天晚上""今天凌晨"等会过期的时间锚点不写，用"X 月 X 日"或省略。
7. **碎段合并**：同一论点的相邻短段并为一段，全文段数往下压。

**保留项（去 AI 味 ≠ 去人味）**：口语化吐槽和松弛感必须保留——「更劲爆的是」「时间线也值得玩味」「对，就是 SpaceX 旗下那个」「用不够也得补差价」这类表达良超原样保留。数据密集段、反问句、犀利判断均保留。

**但 2026-11-02 第二次实证把"保留"的边界收紧了**（见下节）：技术性吐槽（"作者的取法简单粗暴"）保留，**自谦卖萌式插入语**（"（我小时候玩万花筒只看到花，人家玩万花筒直接玩进了 CVPR，惭愧。）"）删。

## 清单 / 榜单类稿件的正式化（2026-11-26 良超定）

> 触发原话：「表格中"一句话简介"换成"简介"你正式点呀，不要这样；既然评估的对象是论文，为什么你不在文中和表格中放DOI；"九届名单看下来"、"2026年这十项"、"从 16 万篇论文里选出 10 项"、"谁在办，办了多久"这种标题太口语了，"总结"、"2026年农业科学十大进展"、"评选规则"、"评选单位"这样的正式表述，会不会好很多？」

1. **小标题正式化**：小标题一律用正式名词性短语（评选规则 / 评选单位 / 2026 年十大重大进展 / 历届变化总结 / 总结），禁口语句式与设问句式——「谁在办，办了多久」「九届名单看下来」「2026 年这十项」「从 16 万篇论文里选出 10 项」这类口语、设问、动词短语标题一律不写。列表项的引导短语同样用陈述式（禁「X 为什么 Y」「X 怎么 Z」设问式开头）。工具/产品安利稿固定小标题「能做什么」「怎么用」豁免。
2. **表格列名正式化**：列名用正式书面名词短语，禁口语化列名——「一句话简介」→「简介」、「成果名」→「成果名称」、「团队」→「主要完成单位」。正文提到表结构时同步用正式列名。
3. **论文榜单 / 成果清单必附 DOI**：盘点对象是论文时（榜单 / 重大进展 / 入选成果这类"以论文为评估单位"的内容），汇总表必设「论文 DOI」列、正文逐项括注 DOI（格式：`DOI：10.xxxx/xxxxx`）。DOI 逐条查证——检索结果或 Crossref API 实际见到该 DOI 字符串才可采用，**禁凭记忆编造**；查不到标「未查到」并注明原因。

selfcheck：检查 31（小标题口语化 ✗）、检查 32（表格列名口语化 ✗）、检查 33（论文盘点/榜单缺 DOI ✗）。

## 强调：绿色高亮替代加粗（2026-11-22 良超定，推翻本条旧「高亮节制」）

> 良超 2026-11-22 原话：「正文如果你现在都给我加粗，那么关键句子或者要强调的名词就用 '#03c160' 这样的绿色来高亮。」

**旧规（2026-11-02 实证：全文 3 处米色高亮被全部去掉 → 默认不用高亮、全文 ≤1 处、强调改用加粗）就此废止**，
连带「搜一搜主旨句用加粗标出」也一并废止（见下「搜一搜」节）。

1. **正文不再用 `**加粗**` 标重点**。结构性加粗（表头、图注编号）由渲染器负责，写稿时不要手写 `**…**` 做强调。
2. 关键句 / 要强调的名词用 `==…==`，渲染器**只把文字染成微信绿 `#03c160`**——不加底色、不加 padding、
   不加圆角、不加阴影（良超 2026-11-22 原话「我不喜欢阴影哈」）；字重与正文一致 500，不叠半粗。
   纯颜色区分，读者看到的是一句绿字，不是一个色块。
   **因果**：2026-11-07 已定正文 16px / 字重 500（半粗体，对标量子位，照顾大龄科研读者），
   正文本身已经足够重，所以强调**不能再靠字重**、只能靠颜色——这正是良超「因为文字都加粗了，
   所以重点才用绿色高亮」的原意。任何在绿字上再加粗、再垫底色的做法都违背这条。
3. 仍然**克制**：每节 1-2 处、只给真正的关键句 / 名词，不整段刷绿、不滥用（否则又变成"到处是重点"）；
   不用于"本文价值 / 我的判断"这类元评论句（去元叙事铁律照旧）。selfcheck 检查 5.4 对 >8 处给 ⚠。
4. 强调色是全号唯一值：`src/md2wechat.py` 的 `ACCENT_GREEN`（章节 h2 左边框同色）。

## 排版基准

- **必须配图**（良超 2026-10-27 反馈；**2026-11-03 密度升级**）：全文字不行，公众号文章至少配 1-2 张正文图（封面不算）。图随文走，插在信息密度最高的章节；图片必须承载真实信息（数据图表、原文截图、结构示意图），用 Wong 色系，经 `scripts/svg2png.py` 或一手来源截图产出，走 uploadimg 上传不占素材配额。
  - **视觉密度铁律（2026-11-03 良超原话：「公众号是类似 PPT 的视觉产品不是文本产品」）**：**每个 ## 主要章节至少 1 张正文图，非文献学习类全文 ≥3 张**（流程、对比、结构、时间轴、数据都可图化）；表格优先图片化；文献学习栏目维持原文图底线但同样鼓励图随文走。自检脚本已同步该规则。
  - **预览可见性**：预览 HTML 用相对路径引用 assets 图，在部分浏览器预览面板里会加载失败——交付预览时必须确认图真的显示出来（必要时把图内嵌进预览 HTML 或随预览一并交付图文件）。良超看不到图 = 没配。
  - **信息图连线纪律（2026-11-03 良超原话：「线为什么没有搭在方框上？能用直线的地方为什么要用斜线？」）**：框图/流程图/生态图的连线，① 端点必须精确落在方框边缘（中点对中点），被卡片遮挡的部分要从卡边缘起算可见段，禁止悬空、禁止差一点没搭上；② 能用水平/垂直直线就不用斜线或曲线，直角正交优先；③ 有流向的连线带箭头，方向与数据/调用流向一致；④ 此类几何问题脚本查不了，归入 L3 视觉审核——每张带连线的图，ViewImage 自检时逐线核对端点。
  - **信息图容器纪律（2026-11-03 良超原话：「太 AI 了……不同类型的文字用一个胶囊给它框住，做图的时候用圆角矩形或者是胶囊这些增加设计感，不然太 AI 了」）**：信息图里**同类型并列的信息项**（规格、清单、步骤内容、对比项）必须用**胶囊（pill）或圆角矩形容器**承载，禁止把并列文字裸排在卡片上；注脚与说明性小字除外。裸文字列表是"AI 味"信息图的典型特征，L3 视觉审核时逐卡检查。胶囊样式基准（2026-11-06 良超改，旧「浅底软色+深字」废止）：高度 40-48px、全圆角（rx=高的一半）、**亮色实底 + 白字**（Wong 饱和色 #009E73 / #E69F00 / #0072B2 / #D55E00 填充，字 #FFFFFF）。良超原话：「我喜欢图一这样的亮色，不喜欢图二这样的浅色，你可以将那些胶囊改成前面的那种亮色，文字用白色，这样看着舒服点」。卡片左侧色条沿用同组亮色（图一那样的亮色锚点）。L3 视觉审核时逐个胶囊核对：浅底软色（#E6F4EF 这类）即不合格。
  - **信息图去辅助标签纪律（2026-11-23 良超原话：「以后公众号作图的时候要避免不必要的辅助标签和说明，让布局本身发挥解释作用，记牢了哈」）**：作图时**让分区、对齐、连线、色彩与位置关系承担解释**，不再叠加辅助性文字。具体：① 不写"步骤 / 阶段 / 模块 / 说明 / 注解 / 示例"这类元标签；② 位置、分组、箭头已经能表达的关系，不再补一句文字解释；③ 不为每个元素配一行释义小字，术语与读图要点放正文或图注；④ 分区标题只在分组本身不足以区分时保留，且用信息词（如"浅层 / 中层 / 深层"），不写"第一部分"式编号标签；⑤ 图注仍在图外按科研三件套写，**图注不属于图内辅助标签**，不因此删减。自检方法：把这段文字遮住，只看布局能否读懂关系——能读懂就删。属 L3 视觉审核，每张自绘图 ViewImage 时逐项过。
  - **引用块不再做视觉强调（2026-11-23 良超看草稿截图定）**：图一 CTA「点击阅读全文，查看论文原文地址」米色底改**灰底 #F5F5F5**；图二文末核对与许可说明（`> 引用`）**没必要再强调**，渲染器 blockquote 改为普通灰字 14px、无底色无圆角卡片。落点：`templates/source_cta.html`、`src/md2wechat.py` STYLES["blockquote"]。
- 正文 16px / **字重 500（半粗体）** / 行高 2 / 字距 .034em / 两端对齐；段落 ≤4 行；图随文走；**小标题见「小标题中性化」节**（文献学习栏目用中性信息词，资讯/观点类仍可让小标题带结论）。**字号字重 2026-11-07 良超定**（原话：公众号属于 PPT 那样的视觉产品，不是 Word 那样的文字产品，很多大龄科研人眼睛不好；对标量子位的加大加粗正文，15px 常规体废止）。
- **图注科研规范化（2026-11-07 良超定）**：正文每张插图必须带图注，格式为科研三件套——**图编号 + 图标题 + 图中元素解释**，左对齐（旧居中 13px 小灰字废止）。写法：Markdown 图片 alt 按「标题：元素解释」撰写即可，**「图N」编号由渲染器按出现顺序自动补并加粗**（alt 里手写了「图N/表N」则尊重原作者编号）；元素解释要点出图中色块/箭头/分区各是什么，让读者不看正文也能读懂图。渲染样式：14px / #595959 / 左对齐，编号加粗深色。selfcheck 检查 17：alt 空 ✗，无「：」⚠。
- 渲染器扩展语法：`++下划线++`、`==绿色高亮==`（#03c160，替代加粗做强调，见「强调：绿色高亮替代加粗」节）、`~~删除线~~`；全角括注 `（…）` 自动灰化（#64748B，见「全号统一写法与排版」§3）；引用块为普通灰字 14px、无底色无卡片（2026-11-23 良超看草稿后定「没必要再强调」，旧米色提示卡废止）。
